What each task is actually about

One line each, then the few things most worth remembering.

2.1

Agentic AI & Tool Integrations

When the system has to work out its own next step — agents that reason, call tools, and know when to stop.

  • Reason, act, observe, repeat. The agent gets tools and an objective, not a fixed path. A Bedrock Agent is just the model, the instructions, and action groups.
  • Action groups are not a security boundary — IAM is. Give the Lambda dynamodb:GetItem on one table, never dynamodb:*.
  • Memory comes in three tiers: session state in ElastiCache or DynamoDB, a decision scratchpad in DynamoDB, long-term patterns in S3 or a Knowledge Base.
  • Workflow chain-of-thought beats prompt chain-of-thought: each step persists, so when step 4 fails, steps 1–3 survive instead of being redone.
  • Confidence decides who signs off: above 0.9 runs itself, 0.7–0.9 is reviewed afterwards, below 0.7 waits for a human — and a wait token pauses the workflow rather than killing it.

2.2

Deployment Strategies

Where the model physically runs, what that costs, and why deploying an LLM breaks every habit from traditional ML.

  • The timeout trap: a 100 GB+ model takes 20–40 minutes to pull from S3 into GPU memory, but default health-check timeouts are 5–10 minutes — so AWS declares a perfectly healthy container dead. Raise them to 60 minutes.
  • On-demand vs Provisioned Throughput: pay per token when traffic is uneven; buy Model Units when steady volume cannot tolerate throttling — and accept that you pay for them when traffic drops.
  • Custom Model Import is the economics trick: fine-tune in SageMaker, import into Bedrock, and get your own model on pay-per-token pricing instead of a GPU billed around the clock.
  • Multi-model endpoints do not work for LLMs. They assume seconds-long cold starts. Use inference components, or swap LoRA adapters against one base model that stays resident in VRAM.

2.3

Enterprise Integration Architectures

Plugging GenAI into a bank that cannot be rewritten — legacy protocols, private networks, and one governed way in.

  • Endpoint type follows the caller, not the workload: edge-optimized when users are spread across 30+ countries, regional when the caller is already in-region.
  • The legacy system is never touched. Mapping templates turn XML/SOAP into JSON and back; a Lambda adapter handles EBCDIC and fixed-width files.
  • Webhooks arrive more than once. An event ID checked against DynamoDB with a TTL is what stops you paying for the same inference — and sending the same email — twice.
  • If the data cannot move, move the model: Outposts for residency, Local Zones for distance, Wavelength for 5G.
  • The GenAI Gateway is the one front door: per-team usage plans, Cedar policies, central guardrails, caching and cost attribution. Swap the model underneath and no team changes code.

2.4

Foundation Model API Integrations

Calling the model like a production dependency: timeouts, retries, streaming, and what happens on a bad day.

  • Timeouts are stratified by the job: 4–5 seconds for a clinician standing with a patient, 15–30 for classification, up to 120 for long synthesis.
  • Jitter is the point, not the backoff. Without random variance, every client that timed out together retries together and takes the service down a second time.
  • SSE beats WebSockets for generation — the client has nothing to say mid-stream, and Last-Event-ID resumes at event 48 instead of regenerating the whole answer.
  • Route-level limits matter most. A heavy reasoning model may handle 50 RPS where a classifier handles 500; rely on account-level limits and the heavy one gets crushed.
  • Circuit breaker tuning: 50% failures over 10 requests trips it, 30–60 seconds before recovery, then only 10–20% of traffic in half-open to test the water.

2.5

Application Patterns & Developer Tools

The parts people actually touch — the interface, the business system behind it, and the tooling around both.

  • Four tiers of timeout must line up: Model < Lambda ≤ API Gateway < Client. Get the order wrong and the gateway returns 504 while Lambda keeps burning resources invisibly.
  • Streaming output is invisible to a screen reader unless the container is an ARIA live region. That is a requirement, not a nice-to-have.
  • Enhance, don’t replace: Lambda writes a sentiment score into a field on the existing CRM record. The CRM itself is never rewritten.
  • Retrieval logs assign the blame. If the answer was wrong but the retrieved chunks were already irrelevant, the model did its job — the fault is upstream.
  • Q Business and Q Developer are not the same product: one answers enterprise knowledge seekers, the other works inside your repository.

Why the same thing keeps coming up

Some ideas appear in several tasks. That is not repetition — each task uses the same tool for a different job. Knowing which task owns the detail is half the battle in the exam.

Step Functions, four different jobs
2.1 controls the macro shape of an agent’s reasoning loop so it cannot wander. 2.3 runs parallel and map states over a thousand transactions. 2.4 uses Choice states to pick a model. 2.5 splits one document into sections and processes them at once.
Model cascading, two reasons to want it
2.2 frames it as cost — a small model answers about 80% of queries for a fraction of the price. 2.4 frames it as routing — confidence under the threshold escalates, carrying the partial context forward. Same mechanism, different motive.
Retries, jitter and circuit breakers
2.4 has the numbers. 2.1 makes the breaker one of five layers that stop an agent looping forever. 2.5 splits it by status code: 429 retries almost immediately, 5xx backs off exponentially, 4xx never retries at all.
Caching, three different caches
2.2 separates the embedding cache from the response cache. 2.3 stacks them across gateway, ElastiCache and database. 2.5 adds the client-side one that matches at 85–95% similarity rather than exact text.
Confidence thresholds, gating different things
2.1 uses 0.7 and 0.9 to decide whether a human sees it. 2.4 uses roughly the same band to decide whether to escalate to a bigger model. 2.5 sets 80–90% for critical decisions. The number repeats; what it gates does not.
Observability, split in two
2.4 is the measuring side: subsegments, annotations, p50/p90/p99. 2.5 is the debugging side: Logs Insights over raw logs, the prompt registry that tells you v8 doubled the prompt yesterday, and the retrieval log that decides whose fault it was.
Timeouts, three unrelated senses
2.4 sizes them by how hard the job is. 2.5 makes sure the four tiers are ordered. 2.2 warns about the one that catches people out — model loading taking 20–40 minutes.
