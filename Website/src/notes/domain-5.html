What each task is actually about

One line each, then the few things most worth remembering.

5.1

Evaluation Systems

Deciding whether the thing is good enough, without a single right answer to check against.

  • Traditional ML has one correct answer. GenAI does not. So you stop measuring accuracy and start scoring several independent dimensions — relevance, factual accuracy, consistency, fluency.
  • The dimensions really are independent. A response can be perfectly fluent and completely wrong, or strictly accurate and entirely off-topic.
  • A model can mark the homework, but never its own. Self-preference bias is the reason the judge has to be a different model, and a written rubric is what stops the scores drifting.
  • Customers cannot catch what sounds authoritative. Confident hallucinations and quiet compliance breaches need a domain expert in Ground Truth, not a thumbs-down widget.
  • Change the test set and the scores stop meaning anything. v7 and v8 are only comparable if the evaluation dataset is versioned alongside the prompts and weights.
  • The gate is the point. Automated thresholds block the release so nobody has to make that call under deadline pressure.
  • Split RAG in two before blaming anything. If retrieval returns good context and the answer is still wrong, the generator is the problem — not the vector store.

5.2

Troubleshooting

Five symptoms in a live clinical assistant, and where the fault actually turned out to be.

  • Truncation is silent. Overflow the context window and nothing throws. The model drops the tail and writes a confident, incomplete answer — which in a medication list is the dangerous kind.
  • “API failure” is not a diagnosis. 400, 429 and 500 are three unrelated bugs. Classify them in structured logs before changing a line of code.
  • Two of the five faults were not in the model. X-Ray found the latency in the auth middleware, and 40% of the failures were malformed client payloads that never reached Bedrock — fixed by one pre-call Lambda.
  • More instructions make it worse. Long, nested, conflicting prompts create instruction competition; the model starts dropping constraints.
  • Chain-of-thought as a debugger, not a feature. Making the model show its reasoning is how you find the step where it went wrong.
  • There is no best ANN algorithm. LSH, HNSW, IVF and PQ trade speed, recall and memory differently — benchmark them on your own data.
  • Domain fit beats dimensionality. If the embeddings cluster badly, a bigger vector will not save you; the model simply does not know the vocabulary.

Why the same thing keeps coming up

The two tasks are the same toolkit pointed in opposite directions — 5.1 uses it to decide, 5.2 uses it to diagnose. Knowing which task owns the detail is what the exam is testing.

The same tools, judging vs. diagnosing
5.1 runs A/B tests to pick a winner before release. 5.2 runs the same A/B machinery to find out why two near-identical prompts disagree in production.
Split retrieval from generation
5.1 builds Retrieve-Only and Retrieve-and-Generate as two separate evaluations. 5.2 is what that buys you: when literature comes back irrelevant, you already know whether to look at the embeddings or the generator.
Prompts are code
5.1 versions them with the weights and the test set so scores stay comparable. 5.2 adds the rollback trigger — v8 scores worse than v7, so traffic goes back to v7 automatically. 5.2 then watches for the slow rot: leaked placeholders, meta-discussion, conflicting constraints.
Chunking, yet again
Task 1.5 chunks for retrieval quality and Task 4.1 chunks for cost. 5.2 chunks to stop silent truncation, and 5.2 again to keep a research finding attached to the methodology that qualifies it. Same knob, four different reasons.
Experts in the loop, twice
5.1 uses SageMaker Ground Truth to establish authoritative ground truth. 5.2 feeds the same physicians' ratings and manual edits back into automated prompt refinement. Evaluation input, then optimisation input.
Look outside the model first
5.2 is blunt about it: the auth middleware caused the timeouts, and the client caused 40% of the errors. Before tuning a prompt or swapping a model, trace the request end to end.

Coming from the other maps? Domain 1 builds the system, Domain 2 integrates it, Domain 3 keeps it out of trouble and Domain 4 runs it efficiently. Domain 5 is the one that asks whether any of it actually works — and gives you something to do on the morning it stops.
