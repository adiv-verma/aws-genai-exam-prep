Task 1.1 — Architecture & PoC

Scenario: a multilingual customer-support assistant.

Owns the shape of the whole system — which AWS platform you build on, how a request gets in, and which managed pieces do the work. Every other task fills in one of its boxes in more detail.

  • Build vs. buy: Q Business for turnkey employee search, Bedrock for custom RAG, SageMaker when you need the GPUs.
  • Streaming: AppSync subscriptions over WebSocket; the async-mutation pattern returns a conversationId immediately so the 30-second integration timeout never fires.
  • Hard rule: OpenSearch Serverless is mandatory when a Bedrock Knowledge Base ingests SaaS sources (SharePoint, Salesforce, Confluence).
  • Flows vs. Agents first appears here: deterministic node graph vs. ReAct tool choice.
  • Async plane: EventBridge fans out fire-and-forget, SQS absorbs spikes and queues flagged interactions.

Task 1.2 — FM Selection & Lifecycle

Scenario: clinical document extraction at 50,000 docs/day.

Owns the model itself — choosing it, adapting it, proving it is good enough, and catching it when it degrades months later.

  • Thresholds before benchmarks, or you rationalise whatever you tested first. Capability filters (multimodal, 100k+ context) run before any scoring.
  • LoRA: base weights frozen, a trainable adapter under 1% of parameters, swappable without rebuilding anything.
  • Three-tier gate: automatic metrics → LLM-as-a-judge → human sign-off. Latency and cost are not part of model evaluation — they need separate load tests.
  • BLEU = precision, ROUGE = recall, and both are word overlap: "no chest pain" vs. "chest pain" can still score well.
  • Drift is the long-tail failure: new drugs, new ICD-10 codes, new shorthand. Flagged cases return to the training set as LoRA v2.

Task 1.3 — Data Preparation

Scenario: 5,000+ multimodal insurance claims a day.

Owns everything upstream of the model — validating raw input, processing four modalities in parallel, fusing them, and shaping the final payload and parameters.

  • Four validators, not one: Glue Data Quality for known unknowns, Data Wrangler for unknown unknowns, Lambda for domain logic, CloudWatch for the trend. Failed records go to a human queue — never dropped.
  • Step Functions, not Lambda, orchestrates the fan-out: Lambda’s 15-minute ceiling breaks on long call recordings.
  • Fusion is the payoff: the form says front bumper, the photo shows the rear, the call says rear-ended — that contradiction is the fraud signal.
  • Inference parameters: temperature 0.0–0.2 for financial determinism; tune temperature or top_p, never both; max_tokens caps output only.
  • Stateless FMs: full history is re-sent every turn, so use a hybrid sliding window (summarise old turns, keep recent ones verbatim).

Task 1.4 — Vector Stores

Scenario: a global law firm, 15M documents, 30 countries.

Owns where the vectors live — store selection, metadata frameworks, sharding and caching for sub-second queries, and the security boundary around multi-client data.

  • One store is not enough: Bedrock KB for public corpora, OpenSearch + neural plugin for confidential files, RDS+S3+Pinecone/Faiss for metadata-first pipelines, DynamoDB for live status flags.
  • Pre-filter, then vectorise: RDS narrows 15M documents to 5 candidate IDs by court and year before any vector math runs.
  • The neural plugin embeds the query text inside OpenSearch at query time — no client-side embedding call.
  • Metadata can veto a perfect match: a 100% semantic hit that the cross-reference graph marks as overturned must be blocked.
  • Scale: shard by practice area, fan out in parallel, cache the boilerplate. FGAC is evaluated before results are returned, not filtered afterwards.

Task 1.5 — Retrieval Design

Scenario: the same law firm, judged on retrieval quality.

Owns retrieval quality — how documents are cut, how they are vectorised, how a raw question is reshaped, and how candidates are re-ordered before the model ever sees them. 1.4 is the infrastructure; 1.5 is the accuracy.

  • Chunking is per document type: fixed, structure-aware, hierarchical parent-child, semantic, none, or custom Lambda. Search the child, send the parent.
  • Attach metadata during chunking — adding it after the vectors exist means re-ingesting the whole corpus.
  • Titan Text Embeddings = 1,536 dimensions (V2 also 1024/512/256). Binary embeddings cut storage ~32×.
  • Two golden rules: same embedding model for ingestion and query, and redact PII before embedding — a vector cannot be un-redacted.
  • Two-stage retrieval: hybrid dense+BM25 pulls ~100, a reranker cross-attends and keeps 10. Multi-tenancy is silo / pool / bridge, and pool filters belong in the query layer.

Task 1.6 — Prompt Engineering & Governance

Scenario: a regulated global banking assistant.

Owns the prompt as a production code artifact — what constrains the model, what remembers the conversation, what tests a change, and what proves after the fact which version was live.

  • Three layers, none sufficient alone: system prompt instructs, Guardrails block (outside the model, so prompt injection cannot reach them), JSON Schema enforces shape — a required disclaimer field is deterministic, an instruction is not.
  • Guardrail thresholds invert intuition: LOW is the strictest setting, HIGH blocks only extreme content.
  • State: Comprehend returns a confidence score, below 0.70 Step Functions asks a clarifying question instead of guessing; DynamoDB TTL is a retention control, not housekeeping.
  • Regression over unit tests: v7 and v8 both run the golden dataset; International Transfers dropping 91% → 73% blocks the deploy even though joint accounts improved.
  • CloudTrail vs. CloudWatch: CloudTrail records who invoked which prompt version (7-year audit); CloudWatch records the payloads (debugging). Rollback is repointing v8 to v7 — no redeploy.
